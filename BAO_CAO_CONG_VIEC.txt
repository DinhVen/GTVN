TÓM TẮT CÔNG VIỆC THỰC HIỆN ĐỒ ÁN: NHẬN DIỆN BIỂN BÁO GIAO THÔNG BẰNG EMBEDDING
================================================================================

Tài liệu này tổng hợp lại toàn bộ các phần việc đã thực hiện trong mã nguồn (Source Code) và cách hệ thống hoạt động để phục vụ cho việc Viết Báo Cáo & Thuyết Trình bảo vệ đồ án.

---------------------------------------------------------
PHẦN 1: TỔNG QUAN PHƯƠNG PHÁP CỦA HỆ THỐNG
---------------------------------------------------------
- Hệ thống áp dụng phương pháp Content-Based Image Retrieval (CBIR) thay đổi cách tiếp cận từ "Phân loại phân lớp" (Classification CNN) sang "Tìm kiếm độ tương đồng" (Similarity Search/Embedding).
- Sử dụng mô hình Vision-Language tân tiến: CLIP (openai/clip-vit-base-patch32) để mã hóa ảnh.
- Thuật toán so khớp: Dùng thư viện lõi FAISS (Facebook AI Similarity Search) để triển khai tìm kiếm vector với phép đo Cosine Similarity (thông qua IndexFlatIP trên các vector đã được chuẩn hóa L2).

---------------------------------------------------------
PHẦN 2: CHI TIẾT CÁC HẠNG MỤC MÃ NGUỒN (SOURCE CODE)
---------------------------------------------------------

1. XỬ LÝ DỮ LIỆU & TIỀN XỬ LÝ ĐẶC TRƯNG (FILE: rebuild_faiss.py)
- Code thực hiện đọc toàn bộ ~3,400 ảnh trong thư mục `dataset_aug` thông qua tập `metadata.csv`.
- Đưa qua CLIPProcessor để lấy giá trị điểm ảnh (pixel_values) và truyền qua mô hình CLIP nhận về vector đặc trưng (dimension = 512).
- Chuẩn hoá norm L2 cho vector và lưu thành mảng `image_embeddings.npy`.
- Khởi tạo `faiss.IndexFlatIP(512)` và nhúng toàn bộ vector vào cơ sở dữ liệu `faiss_index.faiss`.

2. PHÁT TRIỂN BACKEND API (FILE: backend/main.py)
- Ngôn ngữ & Framework: Python + FastAPI + Uvicorn.
- Khi khởi động: Server load trực tiếp mô hình CLIP, file FAISS index và Metadata lên RAM để tốc độ truy vấn ở mức mili-giây (ms).
- Endpoint `/search`: 
   + Cho phép Frontend gửi ảnh (UploadFile).
   + Đi qua model CLIP sinh ra Query Vector (512 chiều).
   + Gọi hàm `faiss_index.search()` trả về Top-K kết quả có Cosine Similarity cao nhất cùng với chỉ mục (index).
   + Ánh xạ chỉ mục ra thông tin mô tả chi tiết từ `metadata.csv` (Tên biển, Nhóm biển, Ý nghĩa, Đường dẫn ảnh). Khai báo kết quả dưới dạng JSON.

3. PHÁT TRIỂN FRONTEND TƯƠNG TÁC (FILE: frontend/src/App.jsx)
- Ngôn ngữ & Framework: Javascript + ReactJS + Vite.
- Thiết kế giao diện (UI) mộc mạc, đơn giản, đúng chuẩn đồ án sinh viên đại học (Sử dụng CSS thuần HTML5 cơ bản).
- Luồng tính năng xử lý Ảnh Input mạnh mẽ:
   + (1) Hỗ trợ tải file ảnh qua nút duyệt.
   + (2) Hỗ trợ thao tác Kéo / Thả.
   + (3) Hỗ trợ tính năng dán nhanh (Ctrl + V) cực kỳ tiện dụng bằng `window.addEventListener('paste')`.
- Tính năng xử lý nhiễu (Cropper): Tích hợp thư viện `react-image-crop` để khoanh vùng (Crop bounding box) biển báo. Mục tiêu chính là loại bỏ 100% bối cảnh ngoại lai như cành cây, bầu trời, và loại bỏ "Text" dưới biển báo để tránh bệnh nhiễu chữ của mô hình CLIP.

---------------------------------------------------------
PHẦN 3: CÁCH GIẢI QUYẾT LỖI TÍNH TOÁN VÀ WINDOWS TRONG QUÁ TRÌNH PHÁT TRIỂN
---------------------------------------------------------
Để trả lời thầy cô hoặc viết vào phần "Khó khăn - Giải pháp":
1. Lỗi xung đột Windows (WinError 1114 DllMain): 
   - Khó khăn: Quá trình load `c10.dll` của PyTorch thường bị Windows giới hạn quyền quản lý đồ họa kép ở hệ máy tính cá nhân.
   - Giải pháp: Downgrade (hạ cấp) PyTorch xuống phiên bản cực kỳ ổn định cho CPU là `torch-2.6.0+cpu` thiết lập phù hợp tuyệt đối để phá bỏ rào cản OS cho FastAPI.
   
2. Lỗi FAISS Dimension Mismatch (2560 vs 512):
   - Khó khăn: File FAISS cũ chứa vector 2560 chiều vì một lý do bất đồng môi trường (có thể từ mô hình cũ EfficientNet), dẫn đến lỗi Internal Server 500 khi dùng CLIP (512 chiều).
   - Giải pháp: Viết lại tool `rebuild_faiss.py`, chạy tự động trích xuất cấu trúc dữ liệu mới chuẩn hóa hoàn toàn tự động lại 512 chiều cho CLIP.

3. Lỗi nhiễu tầm nhìn diện rộng của CLIP:
   - Khó khăn: Ảnh chụp thực tế dính nhiều yếu tố ngoại cảnh (rừng cây, nhà cửa, bảng tên biển báo lớn) làm CLIP đi chệch định hướng nhận diện.
   - Giải pháp: Thiết kế trình cắt ảnh tương tác ngay bước nhận ảnh đầu vào tại Web Client thay vì train mô hình phụ YOLO (Tránh vi phạm cấu trúc đồ án cấm dùng Object Detection).
